# API設計チェックリスト

APIの追加・変更・削除を設計する際は以下を確認する:

## 後方互換性

- 既存フィールドを削除・変更する場合は移行方針を仕様に明記すること
  - 移行期間中の扱い（継続返却 or 即時削除）
  - 切替条件（いつ廃止するか）
  - ロールバック手段

## 命名一貫性

- 同一API内のbool型フィールドは統一したプレフィックスを使う（例: `should_` または `is_`）
- フィールド名はその役割が明確に分かる名前にする

## 冗長性チェック

- 他のフィールドから導出可能なフィールドは不要（例: `a || b` が計算できるなら `c = a || b` は返さない）
- レスポンスに含める情報は受信側が自力で計算できないものに限定する
